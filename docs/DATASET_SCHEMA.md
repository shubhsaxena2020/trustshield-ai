# TrustShield text dataset — schema, taxonomy, policies (Phase 3 contract)

This file is the contract every data producer and every script follows. Changes require the coordinator's approval.

## Labels
**Level A — `binary_label`** (primary evaluation layer): `legitimate` | `malicious_or_fraudulent`.

**Level B — `category_label`**: `legitimate`, `phishing`, `credential_theft`, `payment_fraud`, `fake_job`, `investment_scam`, `impersonation`, `digital_arrest`, `delivery_scam`, `prize_lottery_scam`, `other_fraud`, plus `unlabeled` (allowed ONLY for public-dataset records whose fine category was not annotated; they count in binary metrics but are excluded from multiclass metrics).
Category definitions (annotators use these, most specific wins):
- `phishing`: link/lure impersonating a bank/service (KYC update, account blocked, verify now) whose main mechanism is a deceptive link or page.
- `credential_theft`: asks the reader to reveal OTP/PIN/CVV/password/card/net-banking details (by message, reply or call).
- `payment_fraud`: demands or tricks a payment (fake fee, wrong-transfer refund request, collect-request/UPI-QR scam, fake invoice).
- `fake_job`: job/work-from-home/task offers with fees, easy money, or WhatsApp/Telegram-only hiring.
- `investment_scam`: guaranteed returns, trading tips groups, crypto doubling, fake IPO/loan schemes.
- `impersonation`: pretends to be a known person/authority/company (boss, relative in trouble, customer care, government) to extract action/money, without the digital-arrest coercion script.
- `digital_arrest`: police/CBI/customs/court coercion, "arrest", secrecy, video-call surveillance, "safe account".
- `delivery_scam`: parcel held / address incomplete / redelivery fee lures.
- `prize_lottery_scam`: lottery/prize/reward/cashback/free-gift claims.
- `other_fraud`: clearly malicious/fraudulent but none of the above (e.g. romance, sextortion, tech-support, loan-app harassment).
- `legitimate` (only with binary `legitimate`): real notifications and ordinary text, INCLUDING deliberately hard controls that share vocabulary with scams (bank debit/credit alerts, genuine "never share your OTP" warnings, real OTP messages, payment confirmations, e-commerce shipping/delivery notices, HR/interview scheduling, college notices, telecom/utility reminders, ordinary chat, marketing that is clearly legitimate).
Categories with too few samples must be merged or marked under-supported in the report; never present a class with a handful of samples as if it were meaningful.

## Record schema (JSONL, one object per line; also exported as CSV)
`id` (str, stable: `<source_short>-<8 hex of sha1(normalized text)>`), `text` (str), `binary_label`, `category_label`, `source_type` (`public_dataset` | `synthetic` | `manually_curated` | `legitimate_control`), `source_name` (str; for synthetic = the generating tool/model name + set name; for public = dataset name), `synthetic` (bool), `language` (`en`), `date_added` (ISO date), `split` (`train`|`validation`|`test`, filled by prepare_dataset), `duplicate_group` (str, filled by prepare_dataset), `notes` (str; license/attribution pointers, hardness tags such as `hard_negative`, `obfuscated`, `short`).
`source_type` rules: `synthetic` = written/generated by an AI or a template; `manually_curated` = hand-written or hand-adapted by a human; `public_dataset` = imported unchanged from a published dataset; `legitimate_control` = legitimate control messages (may additionally be synthetic — then `synthetic=true`). `synthetic` must always be the truth.
No real private individuals' messages, no real phone numbers/account numbers/emails: use obviously fake data (e.g. 98xxxxxx00-style placeholders are NOT allowed as they hurt realism; use invented but non-real numbers/IDs). Malicious URLs must use invented domains (not real organisations' real domains except in legitimate records that legitimately cite an organisation's real official domain).
Language scope: English (Hinglish/romanised Hindi may appear in public data but is out of scope for claims).

## Layout
- `datasets/raw/<source>/…` raw inputs as fetched (+ per-source `SOURCE.md`: URL, license, retrieval date, sha256, mapping applied). Raw public data is committed only if its license allows redistribution; otherwise the fetch script reproduces it.
- `datasets/processed/trustshield-text-v1/all.jsonl` (unified + provenance, pre-split), `train.jsonl`, `validation.jsonl`, `test.jsonl`, `manifest.json`, `duplicate_groups.json`, `dedup_report.md`.
- `models/trained/…` serialized artifacts + `models/metadata/…` provenance; `models/evaluation/…` reports/plots/CSVs.

## Splitting policy
Deterministic (seed 42). Dedup BEFORE splitting: exact duplicates and normalized duplicates (lowercase; digits→`0`; URLs→`<url>`; whitespace collapsed) are collapsed to one record (keep the record with more provenance information; log removed ids). Near-duplicates / template variants (character-shingle Jaccard or TF-IDF cosine above a documented threshold, plus identical normalized-template signatures with named entities/amounts masked) are grouped via union-find into `duplicate_group`. A group never spans two splits. Split ≈70/15/15, group-aware, stratified by (binary_label, category_label) where feasible. Records whose `source_name` starts with `holdout-` (an independent author/tool, generated without seeing the training data) are assigned ENTIRELY to `test` (a cross-author generalisation slice), and this is reported separately. The test split is untouched during feature design, model selection, hyperparameter tuning, calibration and threshold selection; every evaluation run on it is appended to `models/evaluation/test_access_log.json`.

## Decision definitions (fixed a priori, before any test result exists)
- ML-only alert: calibrated P(malicious) ≥ the threshold selected on validation.
- Rule-only / combined alert: TrustShield `risk.score >= 25` (label `caution` or higher). Secondary operating point reported alongside: `risk.score >= 50` (`suspicious`+). Threshold-free comparison: ROC-AUC / PR-AUC over `risk.score`.
- No weights, bands or rules are tuned in Phase 3 before all three systems (rules, ML, combined) are measured on validation and test.
