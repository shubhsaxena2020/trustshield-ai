# GitHub, review and handoff workflow

Base branch `android-finals`; one short-lived `android/<package>` branch per implementation package. Issue labels: `android` and exactly one `p0`, `p1` or `p2`; keep old #2/#3/#4 and other finals issues unchanged unless a package actually resolves them. One issue exists for each A01–C09 in `WORK_PACKAGES.md`. Commit every meaningful unit with `feat:`, `fix:`, `test:` or `docs:` and `Refs #N`; push after medium chunks. Worker hands code to Codex; only Codex commits/opens/merges PRs. PR body has a checklist for scope, build/tests, safety, UI/device evidence and known gaps. `Closes #N` only for fully accepted packages. Comment exact results on the issue; close on merge when done.

Codex verifies package output locally, reviews every changed file and cross-checks the hard rules. One package owns each file. Shared Gradle, manifest and cross-module wiring is reserved for Codex and changed in a reviewed integration commit. Do not merge a claimed test from a worker without rerunning it. If green, merge PR into `android-finals` without force or history rewrite, pull/verify head and update `docs/android/STATE.md` and append-only `ORCHESTRATOR-LOG.md`. Push phase results to `origin android-finals`. Claude Code reviews Phase 1 before Phase 2 launches.

Before risky Git operations, use a temporary index to snapshot only intended paths and save the tree with `git commit-tree` under `backup/android-wip-*`; verify the resolved path/ref. Do not stash or discard pre-existing untracked user files. If remote or `gh` is unavailable, keep local commits and record the exact failed operation; do not claim GitHub issue/PR completion.

Worker handoff: issue ID, owned paths, plan and edge cases, exact commands/exits, test/log/screenshot paths, measured device, limitations, and any dependency change requested of Codex. Codex reply: accepted with reproduced evidence, or <=4 concrete defects and retest requirement. The phase report distinguishes observed, inferred and unverified facts.
