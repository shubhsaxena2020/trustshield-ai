# Architecture decision (25 October 2026)

## Choice

Use **native Kotlin + Jetpack Compose**, minSdk 26, compile/target SDK 36, JDK 17 and the checked-in Gradle wrapper. The Phase 1 build proof exercises these exact layers. Native APIs give the shortest route to `SpeechRecognizer`, a foreground mic session, CameraX/ML Kit and `NotificationListenerService` without a plugin bridge. Flutter would add a Dart toolchain that is not installed; React Native adds Node/Metro and native modules for the same privileged paths; Capacitor shares a web UI but still needs native bridges and WebView lifecycle work. None has a demonstrated build on this machine. Kotlin's compile time and fresh Android learning curve are real costs, so the app uses simple modules and limited screens. This is a schedule choice, not a blanket claim that native apps are always faster.

| Criterion | Kotlin/Compose | Flutter | React Native | Capacitor |
|---|---|---|---|---|
| Installed toolchain | JDK 17/SDK 36; Gradle bootstrapped in Phase 1 | Flutter SDK absent | Node 24 present; RN Android project absent | Node present; native bridge project absent |
| Camera/mic/listener | Direct Android APIs | Plugins/platform channels | Native modules | Plugins/custom bridge |
| APK size | Build proof measured in `STATE.md` | Not measured here | Not measured here | Not measured here |
| UI polish | Compose animation/theme/accessibility | Strong widgets | Strong React ecosystem | Existing web skills, WebView cost |
| Three-day integration risk | Lowest once wrapper builds | SDK/bootstrap | Bridge/build | Bridge for hero features |

## Boundaries

`Share/Camera/Mic UI -> bounded input adapters -> local normalization -> local deterministic evidence rules -> local fusion/presentation`. Input adapters never launch a URL, QR destination, file, APK or an external intent based on analysed content. Local rule output uses immutable evidence with `quote` tied to a source span; keep risk score and confidence separate. QR watcher operates on CameraX frames with bundled ML Kit barcode model so decoding works immediately offline. Store only salted/HMAC protected expected payee identifiers and small preferences, not scan payloads. Device keystore/PIN design is a Phase 2 gate; hashing a low-entropy UPI ID alone is not a privacy guarantee.

The existing Python engine remains authoritative for its own API results. `/api/v1/analyze/text`, `/url`, `/image`, `/qr` offer optional online enrichment through an adapter **only after the retention audit passes**. Do not silently replace a local warning with a lower backend score; show source and disagreement, and define merge semantics before shipping. Current backend evidence schema is `{id,source,category,severity,confidence,title,description,metadata,timestamp}` and has no `strength`, `quote`, or `title_hinglish`; an adapter must derive only verified fields or omit them. Current image results include OCR `raw_text` and `normalized_text` in `modules.ocr.data`, and signed-in history stores `input_summary` plus `result_json`. Anonymous API analysis avoids the Supabase write but server/in-memory result retention still needs a privacy audit. Ship local-only analysis if these paths cannot meet the no-content-storage rule. Source: `services/api/main.py`, `services/analysis/pipeline.py`, `services/history/store.py`.

Call Shield is **visible, user-started microphone analysis of audible speech**. Android does not grant ordinary apps reliable capture of the other side of cellular/VoIP calls. Use `SpeechRecognizer.createOnDeviceSpeechRecognizer` only after capability and `hi-IN` support checks on API 31+, and test with airplane mode. `EXTRA_PREFER_OFFLINE` is only a hint. On unsupported phones, use a consent-based Vosk small Hindi model candidate (42 MB download, device timing unmeasured); Whisper.cpp tiny/base is a research fallback, not a promised 10–15 s SLA. No cloud speech path may be labeled private/on-device. Call Shield stage state persists for the active session while the transcript itself is bounded to two minutes. No notification listener is needed for the P0 flow.

## Research evidence and corrections to the report

- Android [SpeechRecognizer API](https://developer.android.com/reference/android/speech/SpeechRecognizer) says on-device availability varies, `createOnDeviceSpeechRecognizer` starts at API 31, and default recognition may stream audio remotely. [RecognizerIntent](https://developer.android.com/reference/android/speech/RecognizerIntent) says `EXTRA_PREFER_OFFLINE` may be ignored. Report R6's faster-whisper laptop flow is not directly an Android APK architecture.
- [Microphone foreground service restrictions](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start) prevent a normal background-start promise; [audio playback capture](https://developer.android.com/media/platform/av-capture) depends on the source app's capture policy. A digital-arrest content demo can use speakerphone or staged speech; it is not automatic phone-call interception.
- [Bundled ML Kit barcode scanning](https://developers.google.com/ml-kit/vision/barcode-scanning/android) is immediately available offline and costs about 2.4 MB; an unbundled model can require a download. The phone must remain pointed at the merchant QR. It cannot passively watch an unattended stand like the R7 ESP32 design or buzz with the phone away.
- [Android share receiving](https://developer.android.com/develop/ui/compose/sharing/receive) uses `ACTION_SEND`/`ACTION_SEND_MULTIPLE` and content URIs; R9.1's PWA `share_target` is for the paused website.
- [Vosk model listing](https://alphacephei.com/vosk/models) lists a 42 MB Hindi model. [whisper.cpp Android sample](https://github.com/ggml-org/whisper.cpp/blob/master/examples/whisper.android/README.md) recommends tiny/base; model size, RAM, latency and Hinglish recognition must be measured on target hardware. R6's 2 GB server RAM is not a phone benchmark.
- The report assumes WhatsApp customer-service replies are free. The [current official platform pricing page](https://whatsappbusiness.com/products/platform-pricing/) describes free service replies within a 24-hour window, while public October 2026 rate-change reports disagree. Treat price/eligibility as unverified before any purchase; WhatsApp is cut from the APK.
- Sideloading avoids a Play listing review; it does **not** make notification access automatic or prove that Play policy is the only obstacle. The [NotificationListenerService API](https://developer.android.com/reference/android/service/notification/NotificationListenerService) requires service declaration and user-granted special access; it can also be unavailable on older low-RAM devices and in work profiles. It does not guarantee every app's content is readable.
- R8's 12-digit UTR and ten-minute age are heuristics, not payment confirmation. R3's “every scam follows stages” is a useful pattern model, not a universal guarantee. R4's 300-real-message holdout cannot be assembled and sealed in this window; no retrain or new accuracy number.
